# Korund

Trainings-App für Athleten im Krafttraining (seit Version 115 Korund, früher Gymstead und Hybridslife, Repo-Name bleibt `hybridslife`). Sie ist bewusst keine Hybrid-App.

## Ziel
- Phase 1: Gym-Workouts tracken (Übung, Sätze, Wdh., Gewicht, RIR, Datum)
- Phase 2: KI-Coach für Krafttraining
- Phase 3: Spiel: Punkte für Training sammeln und eigenes Gym bauen
- Laufen ist nicht geplant (Stand 12.10.2026)

## Technik
- HTML, CSS, JavaScript. Die App läuft heute als PWA auf dem Homescreen des Handys. Eine native App ist erst ein späteres Ziel

## Design

- Ohne Eintrag im Speicher gilt Glass. Klassisch gilt nur, wenn in den Einstellungen ausdrücklich `stil: "klassisch"` steht

## Programmier-Regeln
1. Erst denken, dann programmieren
   - Annahmen ausdrücklich nennen. Bei Unsicherheit fragen
   - Gibt es mehrere Deutungen, zeig sie mir und wähle nicht still eine
   - Gibt es einen einfacheren Weg, sag es mir
2. Einfachheit zuerst
   - So wenig Code wie möglich, nichts auf Vorrat
   - Keine Funktionen, Abstraktionen oder Einstellungen, die ich nicht verlangt habe
   - Wenn es mit weniger Code geht, schreib es kürzer
3. Chirurgische Änderungen
   - Fass nur an, was für die Aufgabe nötig ist. Kein "Verbessern" von Code daneben
   - Halte dich an den vorhandenen Stil
   - Siehst du toten Code oder Fehler außerhalb der Aufgabe, sag es mir, lösch oder ändere nichts
   - Entferne nur, was durch deine eigene Änderung ungenutzt wurde
   - Jede geänderte Zeile muss auf meine Bitte zurückgehen
4. Ziele prüfbar machen
   - Sag vorher, woran wir merken, dass es funktioniert
   - Bei mehreren Schritten: kurzer Plan mit "Schritt → so prüfen wir es"

## Daten und Sicherheit
- Bestehende Einträge, Routinen, Wochenplan und Backups dürfen nie verloren gehen oder verändert werden
- Am Datenformat oder an der Backup-Version nichts ändern, ohne es mir vorher zu sagen. Alte Backups müssen weiter importierbar sein
- Gelöschte eigene Eigengewicht-Übungen (seit Version 105): Beim Löschen merkt sich die App die id der Übung in der Liste `geloeschteEigengewicht` (eigener Schlüssel im Speicher, im Backup ab Backup-Version 11). `istEigengewicht` fragt zuerst die vorhandene Übung und sonst diese Liste, so rechnen die alten Einträge weiter mit dem Körpergewicht. Die Einträge selbst bleiben unverändert. Beim Import kommen die ids aus dem Backup immer dazu, auch beim Ersetzen, Backups bis Version 10 lassen die Liste, wie sie ist. Für Übungen, die vor Version 105 gelöscht wurden, gibt es keine Rekonstruktion: Ihre Einträge rechnen ohne Körpergewicht. Wer eine eigene Übung mit demselben Namen neu anlegt und die alten Einträge verknüpft, bekommt die Werte zurück. Test: `node tests/eigengewicht-test.js`
- Name der App (seit Version 115 Korund): Sichtbar heißt die App überall Korund (Titel, Manifest, Homescreen-Name, Über, FAQ, Teilen-Bild über `APP_NAME` in der `raenge.js`, Backup-Datei `korund-backup-JJJJ-MM-TT.json`). Bewusst geblieben ist die Vorsilbe des Cache-Namens `gymstead-v` in der `sw.js`, damit der Service Worker die Caches älterer Versionen weiter löscht. Neue Backups tragen die Kennung `app: "korund"`, die Backup-Version blieb dabei 11 (seit Version 122 ist sie 12, siehe „Zeit je Satz"). Der Import prüft die Kennung nicht: Backups mit `"hybridslife"`, `"gymstead"`, `"korund"` und ohne Kennung lassen sich alle importieren. Test: `node tests/backup-kennung-test.js`
- Zeit je Satz (seit Version 122, Backup-Version 12): Jeder Satz aus dem Trainingsmodus trägt in `einzelsaetze` das freiwillige Feld `zeit` (ISO-Text, Zeitpunkt von „Satz fertig"). Man sieht es noch nirgends, es ist für einen späteren Zeitverlauf. Weitergereicht wird es an fünf Stellen: `satzFertig` (setzt es), `eintragSaetzeSchreiben`, `saetzeVon`, `satzSpeichern` (Bearbeiten behält die Zeit) und `satzAenderungSichern`. Eine neue Stelle, die Sätze neu baut, muss `zeit` mitnehmen. Ältere Sätze und Einträge aus „Übung eintragen" haben kein `zeit` und bekommen keins. Neue Backups tragen `version: 12`. Der Import prüft die Version nicht und übernimmt Einträge als Ganzes, Backups der Version 11 und älter laden wie bisher, die Version 121 kann ein Backup der Version 12 lesen (sie übernimmt `zeit` mit dem Eintrag und wirft es erst weg, wenn dort ein Satz bearbeitet wird). Tests: `node tests/satz-zeit-test.js` und `node tests/backup-kennung-test.js`
- Status und Notizen (seit Version 141, Backup-Version bleibt 12): `einstellungen.auszeiten` ist eine Liste `{ art: "krank" | "urlaub", von, bis }`. Eine Woche mit Auszeit ohne genug Trainingstage bricht die Serie nicht und verbraucht keine Pausenwoche (`serieBerechnen` in der `raenge.js`, vierter Wert). Trainingsdaten ändern sich nie. Notizen je Übung stehen unter dem eigenen Schlüssel `notizen` (Schlüssel `uebungId` oder `"name:" + Name klein`), im Backup als Feld `notizen`. Import: Ersetzen übernimmt alle Notizen, Ergänzen füllt nur fehlende. Ältere Backups ohne diese Felder laden wie bisher. Tests: `node tests/status-test.js`, `node tests/notizen-test.js`
- Aufwärmsatz „W" (seit Version 141, Backup-Version bleibt 12): Ein Satz in `einzelsaetze` kann das freiwillige Feld `aufwaermen: true` tragen. Gesetzt wird es nur über den Knopf „W" (`#modus-w` im Trainingsmodus neben RIR, `#satz-w` im Sheet „Satz bearbeiten"), beide nur im Look Korund zu sehen (`.w-knopf` in der `style.css` ausgeblendet). Nach „Satz fertig" ist „W" wieder aus. Test: `node tests/aufwaermen-test.js`
